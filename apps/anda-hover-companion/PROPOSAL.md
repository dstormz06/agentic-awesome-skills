# One-pager: Claude API access for the ANDA Hover Companion pilot

*Template for the director ask — adapt names/numbers to your division. Keep to one page.*

**The ask.** Approve API access to Claude (Anthropic) through an agency-approved channel
— practically, Claude on AWS GovCloud / Amazon Bedrock (FedRAMP-authorized path) — for a
small RPM pilot of the ANDA Hover Companion, a Windows tray tool built in-house.

**What it does.** An RPM points at any ANDA number on screen and gets a one-glance card:
official goal date vs. an evidence-based **forecast** (delta, confidence, drivers), the
single item needing attention, what's landing on them next, and a 2–4 sentence
companion brief that flags untested assumptions, applicant patterns, and sister-ANDA
precedent — every claim cited to a note or submission. The forecast number is computed
from historical cycle data, never generated by the model, and the tool publishes its own
calibration so its accuracy is auditable.

**What the API is for.** Only the brief — the synthesis sentence layer. Everything else
is deterministic and already works offline today. The app is built so that granting
access is a config change (set the key, press "Test connection" in Settings), not a
rebuild.

**Data handling.** Minimal-necessary-fields: the model receives the structured card
record (dates, statuses, short note lines), never documents or correspondence bodies;
record content is fenced as data against prompt injection; the app is read-only, stores
no agency data, has no telemetry, and every generated sentence is labeled
"generated — verify before acting." Full threat model: SECURITY.md.

**Cost envelope.** ~3–4K input tokens (mostly cache-served) + ~300 output per lookup ≈
**$0.01–0.03 per lookup**. A 10-RPM pilot at 30 lookups/day ≈ **under $200/month** —
against minutes of system-navigation time saved per lookup, per person, per day.

**Pilot plan (8 weeks).** Weeks 1–2: offline mode on pilot machines (works today,
fictional/sanctioned-extract data), baseline time-to-answer measured. Weeks 3–8: API
enabled; measure median time-to-answer, forecast calibration (median |forecast −
actual|), lookups/user/day, and brief error reports (one-click flag in the app).
Exit criteria and rollback: remove the key — the tool keeps working offline.

**Why this wins for the division.** It's AI where AI is accountable: deterministic
facts, computed forecasts with published accuracy, and a clearly-fenced synthesis layer
— a template for how OGD project management can adopt AI without ceding a single fact
to a model. The architecture is also **provider-pluggable and Elsa-ready**: the model
backend sits behind one interface, so if the agency later standardizes on Elsa or
another approved service, the tool swaps backends with zero change to its grounding,
security, or UI. Goal-date logic is likewise versioned per GDUFA cycle — GDUFA III
encoded today, GDUFA IV a drop-in when its commitment letter finalizes.
