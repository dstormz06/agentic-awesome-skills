# ANDA Companion (Notula)

A prototype for FDA DPM review project managers (RPMs). Select an ANDA number anywhere and a small card shows the goal date
against the forecast, what needs attention, a WATCH line (weekends, federal holidays, passed goals), the PSG and RLD dates, and
a status line to copy. It can also review a draft message against the record, and answer a question about any selected text or spreadsheet cells
(quick checks run on your PC; a prompt of your own is shown to you first and sent only if you press Send).

It comes in two parts that work alone or together:

- **Windows app** (`app/`): a tray app (.NET 8, Avalonia) with shortcuts, the card, a lookup box, the draft check, a watch list, your own
  Excel or CSV portfolio and notes folder, a live **ANDA to-do list**, a separate **My to-do list** for your daily workload, ANDA related or not (rough highlighted notes become suggested items, read by plain rules with no AI), **your own actions** (a prompt, an AI request or an agent request on a
  shortcut you choose), a connector for **agents such as Alert Hub, Patent Analysis and Triaging Agent**, and writing actions that work only through an
  approved provider. Everything you may want to change (keys, files, connection, model name, your own API, your own agents and actions,
  writing style, look, optional Outlook) is in **Settings**, which arranges itself (it opens on what needs a look and keeps the rest collapsed), with no rebuild.
- **Edge extension** (`extension/`): works in Edge and other Chromium browsers. It runs only when asked, on the one tab, with no network
  access. With the app connected (native messaging) it uses the app's portfolio and rules.

**Where the newer design stands (rounds 18 and 19).** New work is built and published first in the browser simulation, for the owner to review, and ported to the Windows app
afterwards. **In the Windows app today:** the Loupe icon (no amber at any size since round 23), the same **eight looks** as the simulation with **X · Graphite Calendar** as the default (round 24: one answer first, the days to the goal date beside it, the calendar under it), **quick notes typed on the card** (Enter goes straight to a new note; Copy status is a small button and the S key), an **Open ANDA page** button with an address set in Settings, a tray icon that shows a dot when one thing needs the person today and the number when there are two or more, a setting for when it is counted again, the
N and A number prefixes (N210793 is an NDA and is refused; A210793 is read as ANDA 210793), the new default shortcuts and, since round 25, **Review with Proofread and Fact-check that work with no AI** (the same fixed rules as the simulation, answer for answer: a marked draft, a corrected draft to copy, strength, review cycle and due date compared with the person's data, one question before sending, and the person's own notes and open items for recall). **Since round 26, in both programs: Compare two files** (two versions of one report, compared on the PC by fixed rules, with a short summary, two simple charts, the list of changes and, if wanted, a narrative through the person's AI after the usual preview), **four reading prompts** in Ask about a selection (TL;DR, what else should I know, onboard me, why does it matter), **a calendar invitation** and **a note on an ANDA** made from a selection with no AI, and **My usage** (counts only, off until switched on, shared only if the person copies them). **Only in the simulation so far:** the blur behind the glass looks, One Bar,
Today, recent and kept ANDAs, spacing and text size (round 18), card details with Copy and notices near the clock with division news (round 19), the on-device AI option in Review,
and a desktop that looks like Windows 11. The card's starting transparency is 90% in both (it was 92%).
**Since round 27, in both programs:** *Compare two files* also compares **two documents** paragraph by paragraph (Word, text and Markdown in the app; text and Markdown in the simulation), runs **one of the person's stored prompts** on what was compared (the differences the rules found; the beginning of each file only when the person ticks the box for that pair, always after a preview), and **checks a pasted AI answer** against the files with no AI; it can check **a report against the person's data** and show **what changed in the person's sheet since last week**; the tray menu has a **hand-off page**; Ask about a selection offers a **meeting page**; and Review a draft lists **signs worth a second look** (not a detector: it never says who or what wrote a text) and offers a **follow-up for a reply**.
**Round 28** changed no feature: it checked the product against the owner's standing rules for a federal desk, had it attacked by an independent reviewer, and fixed what was found (an AI connection is off until chosen; a file of the person's own is never overwritten when it cannot be read; finished items are archived, not deleted; the fence around text for an AI is stronger; the keyboard and a screen reader reach more; no script launcher). What was left, and why, is in `DESIGN.md` §11l and `VERIFICATION.md`.
**Round 29**, in both programs: every window says what is switched on ("Offline · Local only", or each connection by name), with a list of what each connection sends, where and what is kept; an event log that is only added to and holds times, kinds and counts, never content; a page with the version and what changed; and kept copies of the sheet are deleted only when the person asks and confirms.
**Round 30**, in both programs: every change to one of your lists keeps a copy of it on the PC, and one press puts a copy back (the list as it was a moment before stays among the copies, so that can be undone); you choose how many copies are kept; finished to-do items can be searched in the archive and put back on their list; and you choose after how many days a finished item is archived. The app removes older backup copies, says so, and asks before a smaller number removes any; it never removes a list or the archive. A restore is refused unless what is there now could be copied first.
**Round 31**, in both programs: every time the tool shows is written in your time zone (this computer's own, or one of ten you choose in Settings, Look and feel, Time), with the zone's abbreviation and the right daylight time; times are stored in UTC, so changing the zone changes how a time is written and never when it was. Every piece of your data says where it is from, as of when and how long ago, and is marked STALE, in words and by its look, once it is older than the days you choose (7 unless you change it); the card's watch line says so at the same minute. A clock in Settings and the card's data line are brought up to date once a minute while they are on the screen. A compact box writes STALE on itself; a hand-off or meeting page says when it was made and carries the same data line; the app's browser host tells the extension the same line. Which day is "today", for due dates and day counts, stays this computer's day. The Drugs@FDA reference file says when it was saved and how long ago, and is marked STALE after a number of days of its own (45 unless you change it; round 32).
**Round 32**, in both programs: a guide of five short steps (*First steps*) opens by itself once, at the first start; it can be left at any step and is opened again from the tray menu, *Help: first steps*. It asks for nothing and changes none of your settings or data: its buttons open a card of labeled sample data, Settings where your file is chosen, and the list of connections.
**Round 33** brings the other two programs level. **The Windows app** gains five things the simulation has had since rounds 18 and 19: *Details* on an expanded card (columns of your own sheet such as the US agent's email or the team lead, each with **Copy**, and "not in your sheet" where the sheet has none); **larger text** and **compact spacing** (Settings, Look and feel); **recent ANDAs** and a short list you keep with *Keep in my list* on a card, both offered in the lookup window; **One Bar**, a lookup window that also offers Review and Ask as rows to press; and **Today**, a two-pane window of what needs a look, most pressing first (tray menu, with *Show all tools*). **The Edge extension** now says on every card where its data is from, as of when in your time zone and how long ago, marks it STALE after the days you choose, writes that line again as each minute begins, says what is switched on, and has first steps of its own. `mockup/round33-golden.json` (18 views of the details, 32 steps of the lists, 52 sets of One Bar rows, 18 lookup messages, 4 views of Today, the display factors) holds the app to the simulation's answers; the extension's time rules are the simulation's own text, held to the round 31 and 32 answers.
**Round 34**, by the owner's choice, in the simulation and the Windows app (the Edge extension takes the first part): **your shortcut opens the card directly** (Whisper, the small invite first, stays a choice in Settings, *How it starts*; a middle-click still asks first). **The card shows the answer first**: what it says, goal and forecast, what needs you, the first thing worth a look, and the actions; the calendar, Latest, Ahead, the reference dates and the brief are one press away, under **More** or **E**, so the card fits a 1366 × 768 laptop without scrolling. With an AI connection on, the brief is asked for only when you open the card. **A click on the tray icon opens Today**, which is now in the everyday menu; its *Show all, with reasons…* opens the watch list, which no longer has a tray item of its own.
`DESIGN.md` §11b to §11r describe all of this; the browser suites of the simulation are in `tools/sim-tests/`; `mockup/countdown-golden.json` holds the cases of the days-to-goal rule that both programs must answer alike; `mockup/proofread-golden.json` (32 cases) and `mockup/proofread-stress-golden.json` (372 awkward drafts and 8 with a note) hold the simulation's answers, which the app's proofreader and fact checks reproduce exactly; `mockup/compare-golden.json` (20 comparisons, 14 invitations) does the same for round 26, `mockup/round27-golden.json` (14 pairs of documents and one very long pair, 8 answers, 9 texts for signs, 14 reminders, 4 pages, 10 reports, 10 fence cases) for rounds 27 and 28, and `mockup/round29-golden.json` (8 states of what is switched on, 34 events, 13 changes) for round 29, and `mockup/round30-golden.json` (20 moments and their days, 12 sets of copies, 6 clocks that were ahead, 14 views of an archive) for round 30, and `mockup/round31-golden.json` (506 moments written in 22 time zones, 24 ages, 88 data lines, 9 moments at and past the ends, 12 sentences of Settings, 3 pages) for round 31, and `mockup/round32-golden.json` (98 reference files, the five steps of the guide, 20 views of a step, 7 starts) for round 32; `demo/TRIAL-SHEET.md` is the five-task way to judge whether the design helps in daily use.

All data in the demos is fictional. This is a prototype, not an FDA product. It has not been used by a real RPM, on real data, in Edge
itself, or on a managed FDA computer. Please read `VERIFICATION.md` for what has and has not been proven.

## What each thing is for

| Path | What it is | Read or use it when |
|---|---|---|
| `PROPOSAL.md` | The pilot proposal: problem, scope, what is asked of the division | Deciding whether to run a pilot |
| `ROADMAP.md` | Tester feedback, each request's honest status, decisions made on the owner's behalf, the five-minute Drugs@FDA check | Planning the next step |
| `DESIGN.md` | How the card, consent models (whisper, peek first, always), looks and keyboard behavior are meant to work | Changing the interface |
| `SECURITY.md` | What the app and the extension can and cannot read or send, row by row | Talking to IT or security |
| `VERIFICATION.md` | Every claim with its evidence and its limit; every defect found; what each round does not prove | Before repeating any claim to someone else |
| `ELSA-INTEGRATION.md` | How the writing actions connect to the agency's approved model (today through Settings, My API), and what is still unknown | When Elsa API access exists |
| `app/` | The Windows app source, its tests (`AndaCompanion.Tests`) and a preview project | Building or testing the app (`app/README.md`) |
| `extension/` | The Edge extension source, unit tests, browser tests and the golden file the app wrote | Loading it unpacked in Edge (`extension/README.md`) |
| `extension/tests/golden.json` | Cases written by the app's own code that the extension must reproduce exactly | Keeping the two implementations in agreement |
| `mockup/windows-simulation.html` | A browser simulation of the whole experience (card, right-click, watch list, ANDA to-do list, My to-do list and Notes to my to-do list, your own actions and agents, draft check, Settings that arrange themselves, guided steps). Calls no model and no agent, contacts no server, installs nothing | Showing the idea on a managed computer |
| `mockup/appearance-lab.html` | The 22 light looks side by side (T, U and V are new in round 18) | Choosing a look |
| `demo/` | `START-HERE.txt`, `DEMO.md`, a launcher and a sample memo for the demo build | Running the demo build on a machine IT has allowed |

## Run the checks

```bash
dotnet test app/AndaCompanion.Tests                                  # app: 933 pass and 11 are skipped on Linux; the Windows-only tests run on Windows
node --test extension/tests/unit/*.test.mjs                          # extension rules, safety, manifest, service
NODE_PATH=$(npm root -g) node extension/tests/e2e/standalone.cjs     # real Chromium, extension alone (needs playwright)
dotnet build app/AndaCompanion && NODE_PATH=$(npm root -g) node extension/tests/e2e/native.cjs   # extension with the real host
```

The workflow `.github/workflows/anda-companion-windows.yml` builds the app on Windows and Linux, runs the tests, runs the app's on-device self-test on Windows and publishes the demo build.
