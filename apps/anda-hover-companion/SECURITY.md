# Security posture — ANDA Companion (Notula)

Defense-in-depth for a tool that will eventually sit next to nonpublic, commercially
confidential application data. "Bullet-proof" is not a claim any honest engineer makes;
this is the concrete control set, what each control defends against, and what remains
the deployment's responsibility. Current v0 ships with **fictional data only**.

## Threat model & controls

| Threat | Control (v0 = implemented now, v1 = required before real data) |
|---|---|
| ANDA data leaving the authorized boundary | v0: no real data exists in the app. v1: data layer reads only sanctioned extracts; Claude calls go only through an agency-approved channel (e.g. Claude on AWS GovCloud / Bedrock, FedRAMP-authorized); **minimal-necessary-fields** prompt policy — the model receives the structured card record, never documents or correspondence bodies. |
| API key theft | The app **never stores or writes the key** — it reads `ANTHROPIC_API_KEY` from the process environment at call time and never logs it. v1: Windows Credential Manager (DPAPI, per-user) instead of an env var. |
| Elsa token and endpoint (placeholder) | Read from `ANDA_ELSA_ENDPOINT` / `ANDA_ELSA_TOKEN` in the process environment at call time; never stored, never written to settings, and redacted in `ElsaSettings.ToString()` so no log line or exception can print it (tested). The endpoint must be `https://` (plain `http://` only for localhost, for a local test server), so a token never travels in clear text. An error from Elsa becomes a status-only message: the response body is never shown or logged. Until the mapping in `ElsaMapping.cs` is written, nothing is sent at all and briefs stay offline. The Elsa endpoint is a **new outbound endpoint, and is declared here**: it is contacted only when `ANDA_COMPANION_PROVIDER=elsa`, a safe endpoint is set, and the mapping exists. Sending real ANDA records to Elsa needs the agency's own approval; that decision is not made by this prototype. |
| Prompt injection via record contents | Record JSON is fenced in `<record>` tags; the system prompt's highest-priority rule declares fenced content **data, never instructions**. The forecast number, dates, and statuses are rendered from the data layer, so a poisoned note can at worst color the brief's prose — never the facts, never an action (the app takes none). |
| Prompt injection via the Prompt Library | Lenses are user-authored and stored locally in plain JSON the user can inspect; they enter the prompt in a `<lens>` block explicitly subordinated to the grounding rules. A lens can shift emphasis; it cannot suppress grounding, invent facts, or exfiltrate the system prompt. |
| Prompt injection via drafts, notes and the portfolio | A draft, a matching record or a notes snippet reaches a model only inside fenced `<draft>` / `<record>` / `<notes>` blocks that the system prompt declares **data, never instructions**; the user's standing instructions and lens are explicitly subordinate to the grounding rules and cannot change a date or status. The draft is capped at 8,000 characters. A poisoned file can at worst shade the wording of a generated text the user then reads and copies; it cannot change a fact shown on a card, and the app takes no action. |
| Reading the person's own files (portfolio, notes, Drugs@FDA file) | **Read-only, local, and only the paths the person chooses in Settings.** The Excel reader is the app's own (zip plus XML, no Office, no macros, no formula evaluation, no external links followed, DTD processing prohibited); it reads stored cell values only. Hard limits: 25 MB per workbook, 150 MB unzipped, 20,000 rows, 200 columns; notes: up to 300 files, 2 MB each, two folders deep, snippets of at most 200 characters. The file is opened with sharing allowed so Excel can stay open, and is never modified, copied or uploaded. Nothing read from these files leaves the PC unless the person presses Send in an AI action, which shows the exact text first. The app downloads nothing: the Drugs@FDA file is one the person downloads and points to. A file that cannot be read shows a plain message, never a guess. |
| Writing actions (Proofread, Rewrite, Fact-check) | Off until an approved provider is configured; with none, nothing can be sent. Every action shows the **exact text that will be sent** and sends nothing until the person presses Send. The result is shown with a Copy button only: the app never pastes into, replaces text in, or sends from another program. Fact-check sends only the records for ANDA numbers found in the draft, from the same fields a card shows. It reuses the provider seam, so Elsa or any other backend needs its own approval and is not chosen by this prototype. **Not exercised against a live model.** |
| My API (a provider described in Settings) | **A new outbound endpoint, declared here: whatever https address the person enters.** It is contacted only when the person has chosen "My API" as the connection and a brief, a writing action or Test is made. https only (http only for localhost); an address with a user name or password is refused. The token is **never stored**: Settings holds only the NAME of an environment variable, read at the moment of a request, and it is redacted from every printout. The request body is the person's JSON template with `{{system}}`, `{{user}}`, `{{max_tokens}}` and `{{model}}` filled in as JSON-escaped values, so a quote or newline in a draft cannot break out of the string; the result is parsed as JSON before it is sent. An error shows only the status or a fixed sentence, and a reply without text at the chosen path is reported without showing what came back. **Round 15:** the connection never follows a redirect (a redirect could carry the token header to another host), a reply is limited to 2 MB, and each placeholder is filled in one pass, so a value can never be read again as a placeholder. The same fenced-data rules apply as for every provider. Tested against a fake server only; **not exercised against any real service.** |
| My actions (your own prompt, AI request, agent request or to-do item, on your own shortcut) | A shortcut or a tray-menu click is the only start; nothing runs by itself. The selection is read the way Select & Peek reads it (same clipboard hand-off, same refusal in terminals, at most 2,000 characters, control characters removed). *Fill my prompt* calls nothing and only shows text to copy. *Ask my AI* and *Run an agent* show **the exact text that will be sent, with the address for an agent, and send nothing until the person presses Send**; sending at once is an opt-in that applies to one action only. Selected text that goes to an AI or an agent is wrapped in `<selection>` tags that the fixed system message declares **data, never instructions**, and it cannot close its own tag. A reply is plain text in a read-only box: it is never run, never pasted into another program and never passed to another action or agent, and a to-do item is added only from a line the person ticks and a button they press. At most eight actions; a shortcut follows the same rules as the three core ones (two modifiers including Ctrl or Alt, never the Windows key, no duplicates). **Residual:** the preview is as honest as the person's reading of it, and a person can send text they should not; the connection and its approval are the organization's decision. |
| My agents (Alert Hub, Patent Analysis, Triaging Agent and your own) | **A new outbound endpoint, declared here: whatever https address the person enters for each agent (http only for localhost).** It is contacted only when the person presses Run or Send, or has set that one agent to run by itself; an agent that is off, or not fully set up, is never contacted. Alert Hub, Patent Analysis and Triaging Agent are **listed but off and without an address**, because their addresses and formats are not known to this prototype and are not guessed. It uses the same connector as My API (token only as the NAME of an environment variable, never stored; no redirects; 2 MB reply limit; JSON-escaped fill; status-only errors). By itself means **only the card's structured facts named in the agent's prompt and body (number, drug, goal, forecast and so on) and never the selected text**: an automatic agent cannot use `{selection}`, a peek never runs an agent, and the card's own request passes no selection at all. An answer is cleaned (control characters removed, 2,000 characters) and shown in the card's drawer as the agent's own words, never as a fact from the record; it is never run, never passed to another agent, and never added to the to-do list without a click. A finding is kept in memory for 15 minutes by default (0, 5, 15 or 60 selectable), is dropped when the agent's settings change, and is never written to a file. **A backup or a restored file can never switch an agent on:** a restore brings every agent back off and not automatic, and sends My API back to Auto, with the address and variable name kept to read. (The simulation had a hole here before round 15: a restored shortcut could carry markup; fixed and tested.) **Not exercised against any real agent**; tested against a fake server only. |
| The ANDA to-do list | A plain JSON file, `todo.json` in the app's data folder, that the person can read and delete. It is never sent anywhere and is not part of a settings backup. It holds the person's own lines (at most 500, 200 characters each), an optional ANDA number and date, and which items from their data they ticked off or snoozed. It is written by replacing the file in one step, so a crash cannot leave half a list, and a damaged or oversized file (over 4 MB) is ignored rather than trusted. Items from the data are derived on demand by the same rules as the card and the watch list. The list refreshes only while its window is open, never in the background; closing it stops its timer. |
| My to-do list and Notes to my to-do list (round 16) | **A separate feature for the daily workload (any task, ANDA related or not), with its own shortcut chosen in Settings (Ctrl+Alt+L at first; none is allowed) and no network or AI at all.** The person selects notes anywhere and presses the shortcut; the selection is read the way Select & Peek reads it (same clipboard hand-off, same refusal in terminals, clipboard restored). The text is read **on this PC by plain rules** (`NoteParser`: regular expressions with 250 ms limits, no AI, no model, no lookup of any kind) into suggested items that the person can change, untick or leave; **nothing is added until the person presses Add**, unless they chose "Add them at once" for the shortcut, and then an Undo button removes exactly that batch. The notes text is capped at 6,000 characters and at most 30 items are offered. It is shown only as text (Avalonia text boxes do not read markup), never run and never sent. The list is a plain JSON file, `mytodo.json` in the app's data folder, **not part of a settings backup, never sent anywhere**: at most 500 items of 200 characters, a date, a repeat, an optional ANDA number kept so a card can be opened, and a count of items finished per day for the last 60 days (so the window can say what was done this week). It is written by replacing the file in one step; a damaged, oversized (over 4 MB) or hand-edited file is repaired or ignored rather than trusted (control characters removed, bad dates and numbers dropped, duplicate ids replaced, the 500-item limit enforced). The notes the person selects may be sensitive; they are written to `mytodo.json` only as the items the person adds, in plain text, readable by anyone with access to the person's Windows profile. The window refreshes only while it is open (every 30 seconds it checks whether the date changed). Items that repeat come back by themselves; nothing runs when the window is closed. |
| Settings that arrange themselves (round 16) | The only thing kept is **a count of how often each Settings section was opened** (eight names, a number each, in `settings.json` on this PC): no text, no ANDA number, no setting value. It is counted at most once per time Settings is open, halves itself when the total grows, is never sent anywhere, is **not part of a backup** (so a file from another PC cannot plant it), is forgotten by "Forget what I use most" and by Reset, and is not kept at all when "Open the sections that need a look…" is turned off. The rules that decide what opens are fixed and readable (`SettingsAdvisor`); they read only facts the app already has (a shortcut Windows did not register, a portfolio file that could not be read, an AI connection that was not tested, an agent or action that is not ready). |
| Recent ANDAs and *Keep in my list* (round 18; designed in the simulation, **not yet stored by the Windows app**) | **This changes the earlier statement that the app keeps no history of what was looked up.** When switched on (the default in the design), the last eight six-digit numbers looked up are kept in the app's settings on this PC, so the lookup window can offer them. Up to five more are kept when the person presses *Keep in my list*. **Only six-digit numbers are stored**: no notes, no draft text, no selection text, no name. Nothing is sent anywhere. *Clear recents* empties the list at once and switching the setting off clears it and stops the saving; a kept ANDA stays until the person removes it. A settings backup holds the kept ANDAs and the on/off choice, **not the recents**, which are this PC's own history. The residual risk is that someone with access to the PC's profile can read which ANDA numbers were looked up recently, as they could read the portfolio file the person chose. |
| The tray icon and its amber dot (round 18) | The icon is a set of pictures embedded in the program (`Assets/tray-32.png` plain, `tray-32-alert.png` with a dot, `tray-32-2.png` to `tray-32-9plus.png` with a number, round 23); nothing is drawn from a file the person controls. At rest the tray picture carries no amber (round 22). The dot means **something needs the person today**: an action item whose text says it is due today or overdue, or a goal date that is today or has passed, in the person's own sheet; a sample record never raises it. It is counted when the app reads data and, **since round 23, on the schedule the person chooses in Settings**: never, once a day just after midnight (the default), or also every hour. **This is the app's one scheduled read**: a count looks up each ANDA in the data source, which re-reads the portfolio file only if the file changed; it reads nothing else, makes no network request and shows no notification. Choosing *Only when I use the app* restores the earlier behavior. The tooltip says how many ANDAs need attention, never which. In the simulation two more reasons are rehearsed (a mark in the sheet, shown as plain text and cut to 120 characters; a message marked urgent with no reply for two days, only while the Outlook rehearsal is signed in): neither is in the app, and the app does not read mail in the background. |
| Open ANDA page (round 21 in the simulation; **in the Windows app since round 24**) | The button opens one address that the person sets, with the six-digit number in place of `{anda}`. **Only a plain `https` address is accepted** (no other scheme, no user name or password in it, no spaces or markup), it is checked every time the button is pressed, and nothing but the number is put into it. With no address, nothing is opened. The site that receives the request learns that this PC asked for that ANDA's page; it is the person's own system by their own setting. The address is part of the settings backup. **In the app** the address is handed to the default browser through the operating system (`UseShellExecute`), which is the app's only way of opening anything; the app itself makes no request, and with no address set (the default) the button opens nothing |
| The clock (round 21) | The simulation reads the computer's own clock and time zone to show the time and to place the sample dates. It asks no server for the time and sends nothing |
| An AI built into the browser or the PC (round 21; simulation only) | **Off unless the browser already has an on-device model installed.** The page never starts a model download. When one is present, each use shows what will be given to it, runs only on a click, and the answer is marked as unchecked and is Copy only. Nothing leaves the PC. Tried against a stand-in, not a real model. In the Windows app this would be a provider like the others: off until IT approves it |
| Quick notes typed on the card (round 20 in the simulation; **in the Windows app since round 24, by the owner's direction**) | **The first thing the app writes that is the person's own content.** A note is kept by the app in its own file on the PC; the portfolio file and the notes folder are still only read. A note is plain text (500 characters, 50 per ANDA at most), is shown as text and never as markup, and is **never sent anywhere, never shown in a notice near the clock and not included in the settings backup**. In the simulation notes are kept in the browser's own store for the page where that is allowed (Reset clears them), and until a reload where it is not. A person can edit and delete their own notes; project notes from the record cannot be changed. **In the app** the file is `quick-notes.json` in the app's own folder (`%AppData%\AndaCompanion`, or the folder named by `ANDA_COMPANION_HOME`); it is written to a temporary file and moved into place; a file that cannot be read is set aside as `quick-notes.unreadable.json` and never overwritten; keys that are not six digits and entries that are not text are ignored when it is read; the file is not encrypted (it is protected by the Windows account, like the settings file). **Still for IT to decide, and now pressing because the app has it:** whether that folder is the right place, and whether working notes kept there fall under records rules |
| Proofread and Fact-check with no AI (round 20; simulation only so far) | Fixed rules on the PC: no model, no network, nothing sent. Proofreading uses a built-in word list and the names in the person's own data; Fact-check reads the same record the card shows and the person's notes. A corrected draft is **Copy only**, or applied to the box inside the tool's own window: the app never types into an email. A draft is treated as text; nothing is built from markup in it. The AI versions of the three buttons are unchanged: off until a provider is approved |
| The look of the simulated desktop (round 20) | Decoration in the demonstration page only. It is drawn from shapes in the page: **no logo, image file or artwork of Microsoft, of any other company or of the agency**, no request to any server, and the banner still states that the page is a simulation with fictional data and not an FDA product |
| Card details: columns of the person's sheet, with Copy (round 19; simulation only so far) | **No new place data goes.** The expanded card shows columns of the portfolio file the person already chose (applicant, US agent and its email, applicant email, project description, the person's own notes, document locations), and Copy puts one value, or all of them, on the clipboard when the person presses it. **Nothing is looked up on the web**: an applicant's short name comes from the sheet. A cell is shown and copied as text; a formula or markup in it is never run. The person chooses which columns appear. Contact email addresses and personal notes are sensitive: they stay in the person's file and on their screen, and are never part of a notice near the clock or of a backup. |
| Notices near the clock (watch-back; round 19; simulation only so far) | **This changes the earlier promise that the app never speaks unless asked, so it is off until the person switches it on.** A notice is one line, bottom right; it never takes the keyboard, hides by itself, and is limited to 1, 3 or 5 a day. It carries the ANDA number and a short reason from the data by the card's own rules, **never the person's notes**. The app would check at start, when the portfolio file changes and once each morning: local reads only, no network. The residual risk is a notice seen by someone else during a meeting or a screen share; the limit, the absence of notes and Snooze reduce it, and they do not remove it. |
| Division news from a shared Word document (round 19; simulation only so far) | **A push channel, declared here.** The division keeps one Word document in SharePoint. The app would read the copy that OneDrive syncs to the PC, as a local file: no new outbound address, no sign-in by the app, no SharePoint permission of its own. **Anyone who can edit that document can put words on every RPM's screen**, so a line is plain text, cut to 240 characters, never run (no links are followed, no markup is interpreted), limited to lines of the last 14 days, and counted in the same daily limit as the other notices. It cannot be switched on without a document, and a restored backup cannot switch it on. Who may edit the document is the division's control to set in SharePoint. Reading SharePoint directly (Microsoft Graph) would be a new endpoint needing an application registration approved by IT; it is not built. |
| One question before sending (round 19; simulation only so far) | Fixed rules on the PC choose the most important finding of the review and phrase it as a question, or say "No open gaps." No AI, no network. It sees only the text that was selected: **not recipients and not attachments**, and the line says so. It is not advice on whether to reply or to whom. |
| Short number forms (round 19) | "N210793" is an NDA number and is refused like "NDA 210793"; "A210793" is read as ANDA 210793. Before this round a number written with an N opened an ANDA card if an ANDA with the same six digits existed: the wrong-card risk the recognizer exists to prevent. The app, the extension and the simulation agree on 47 shared cases. |
| The connection indicator | `ConnectionStatus` changes only because of what really happened: **Connected** only after a Test, a brief or a writing action succeeded; **Not reachable** after a failure; **Set up, not tested** when a key or an endpoint exists but nothing has succeeded; **Offline** otherwise. It is shown on the card, at the top of Settings and in the tray tooltip. Failure text is a type name or a fixed sentence, never the service's reply. The simulation can never say Connected. |
| Update now (Drugs@FDA file) | **The only network action in My data, and the person starts it.** It fetches the one https address the person pasted (this app does not know or guess FDA's file address), caps it at 250 MB, and keeps the file only if it reads as a real Drugs@FDA data file; otherwise the earlier file is untouched. It sends a generic user agent and nothing about the person. Never automatic, never in the background. The expected host is an fda.gov address; the app does not check that, because the person supplies the address. Not exercised against FDA from the build environment (FDA hosts were unreachable), only against a fake server. |
| Outlook (optional, read-only) | **Off by default; a new outbound endpoint only when the person turns it on and signs in.** Addresses are fixed in code: `login.microsoftonline.com` and `graph.microsoft.com` (or the US Government pair `login.microsoftonline.us` and `graph.microsoft.us`); nothing else is contacted and the person types no address. Sign-in is Microsoft's device flow: the person enters a short code on Microsoft's page, so the app never sees a password. The scope is `Mail.Read` only: no send, write or delete permission is requested. The token is held in memory, is never written to a file, a log or a backup, and ends with the app or **Sign out**. A search is only for a six-digit ANDA number on the open card (anything else is refused before any request), asks for at most 10 messages, and shows sender, subject, date and a 160-character preview as plain text. Mail is never stored and never added to an AI prompt. The tenant name is validated so it cannot change the address. **Written from Microsoft's public documentation and tested against a stand-in server only; never run against Microsoft.** The organization must register an app and allow mail access; the app cannot grant itself access. |
| Settings backup and restore | A backup is one JSON file the person saves and later chooses: settings (including the person's actions, the to-do list shortcut and mode, and the choice about arranging Settings, and the addresses and token-variable names of My API and of the agents), lenses and quick replies. It holds no secret (tokens live in environment variables and in memory), no file location on the PC, no items from either to-do list, and none of the PC's own history (the counts of opened sections). Because a backup can be edited or sent by anyone, **a restore never switches on a connection that sends data or a token off the PC**: My API goes back to Auto, and every agent comes back off and not automatic. Restore reads only the file the person picks, refuses anything too large, damaged or from a newer version without changing anything, and repairs out-of-range values to the defaults. The Claude model name is checked against a plain-identifier pattern before it is used. |
| The optional middle-click trigger | **Off by default.** When on, a Windows low-level mouse hook exists, and only then. It sees the middle-button press and which of Ctrl, Shift and Alt are held (exactly the chosen one, Ctrl by default); it never reads the pointer position, a window or any text, never swallows the click (the program under it still gets it), ignores clicks injected by other software, ignores a repeat within 0.4 s and does its work off the hook thread. Some endpoint-protection products flag mouse hooks, which is the organization's call. The extension has no such trigger on purpose: it would need a script on every page. Checked by the Windows self-test with real injected clicks. |
| Quick replies, tone, style and sign-off | Plain text the person writes, stored in `replies.json` and `settings.json` on the PC. Quick replies are filled in from the card with no AI and no network; a value the data does not have becomes "(not in my data)". Tone, style and sign-off are added to the writing actions' instructions only; they sit under the fixed rules, so they cannot change a number or a date. |
| Usage log | Off by default. When on, one local CSV (`usage.csv`, columns `date,event,seconds`) with event names from a fixed list. It never contains an ANDA number, any text, a person's name or a path, and it is never sent anywhere. Delete the file to clear it. |
| The Edge extension (`extension/`) | **Runs only on request** (shortcut, right-click, toolbar) on the one tab you are in: `activeTab` + `scripting`, **no host permissions**, no always-on content script. Its UI is drawn inside a **closed shadow root** with a constructable stylesheet, so the page can neither read nor restyle it and a strict page policy cannot blank it (tested under `default-src 'none'; style-src 'none'`). Every string reaches the DOM as text, never as markup. A selection inside a password or other sensitive field is never read (tested). After the extension is updated, an already-open tab's old script goes quiet instead of throwing. It makes **no network requests**, has no remote code (MV3, `script-src 'self'`), no analytics and no AI. Settings and an imported spreadsheet live in `storage.local` (never `storage.sync`, so nothing reaches a cloud account). "Scan this page" reads the page's visible text on your click and keeps nothing. **Residual:** a page can see that you selected text (it always could); the copy button writes the status sentence to the clipboard on your click; developer-mode sideloading may be blocked by policy, which is the organization's call. Tested in Chromium, not in Edge itself. |
| The extension-to-app connection (native messaging) | **Optional, current user only.** The `nativeMessaging` permission is requested only when you connect. The host manifest lists **exactly one extension ID**, so the browser refuses any other extension (tested: a manifest naming another ID is refused). The host is the app's own exe, started by the browser with the origin as its first argument; it **never opens a window, reads only what the app already reads (its settings, your portfolio, the Drugs@FDA file), writes no data (the single-file runtime's own extraction of its libraries into a temporary folder, which the app does too, is not data) and makes no network call**. Requests above 1 MB are refused, drafts over 20,000 characters are refused, replies over the browser's 1 MB limit become a short error, and every error is a fixed sentence that never echoes what was asked. The Connect button refuses to run from a development run of the app (it must be the app's own exe). Connecting writes a manifest and one registry value under `HKCU\Software\Microsoft\Edge\NativeMessagingHosts` (no admin rights); Disconnect removes both. The browser starts the host without the app's environment, so the app's data folder is recorded next to the manifest. **Residual:** anyone who can write that registry value or the manifest as you could point the browser at another program, which is also true of every native-messaging host; the extension ID is a public key hash, not a secret. |
| Clipboard exposure (Select & Peek) | The captured selection is used only for the 6-digit extraction, never persisted or logged. The user's clipboard is snapshotted in every plain-memory format before and restored after (via a real owner window; a null owner would empty it). Clipboards over 32 MB are refused rather than half-saved. A hand-off failure reports "Clipboard is busy" and never leaves the clipboard empty. The Settings switch turns capture off entirely: Ctrl+Alt+A then opens the lookup box and **no keystroke is ever sent**. **The same hand-off is used by every shortcut that reads a selection: Select & Peek, Review a draft, the person's own actions, and the to-do list shortcut.** **Residual exposure:** for a moment the copied selection is on the system clipboard, so Windows clipboard history (Win+V), cloud clipboard sync and any clipboard-monitoring or data-loss-prevention tool can see it. Where that is unacceptable, turn capture off; UI Automation capture, which touches no clipboard, is the planned replacement. |
| Synthesized keystrokes (Select & Peek sends Ctrl+C) | Never sent to terminals (Ctrl+C there is an interrupt that kills a running command); waits for Ctrl and Alt to be released so the target never sees Ctrl+Alt+C; a masking key stops the Alt release activating a menu bar. Windows blocks injected input into elevated windows, so the app fails safe there (nothing selected, lookup box). Detected by the clipboard sequence number, not by comparing text. |
| Global hotkey hijack or conflict | Four core shortcuts (peek, lookup, review a draft, ask), the to-do shortcut when all tools are shown and up to eight of the person's own action shortcuts, each rebindable and each validated: at least two modifiers including Ctrl or Alt, never the Windows key, no duplicates, so a typing key can never be captured alone. Registration is checked. A combination another program owns is reported in plain words with the fallback, never silently dead. A second copy of the app is refused with a message rather than fighting for the keys. |
| Ask about a selection (text or spreadsheet cells) | The selection is read the way Select & Peek reads it: one copy, the clipboard put back, nothing in terminals, nothing kept or logged. **Quick checks (describe, duplicates, blanks, totals, compare two columns) run on this PC with fixed rules; no AI, no network, nothing sent.** A stored prompt or an instruction typed in the window is filled in and **shown first**; an *Ask my AI* prompt is sent only when the person presses Send on that preview, only to the connection chosen in Settings, with the selection fenced as data and a fixed instruction not to follow anything written inside it. A stored prompt is never changed (the selection is added to a copy). A table or list is never matched to one ANDA's record. Input is limited to 20,000 characters, 1,000 rows and 30 columns. |
| Word's own shortcuts taken by this app | A global shortcut registered by any program is delivered to that program before the active window sees it. Word uses some Ctrl+Alt+letter shortcuts itself (published lists give Ctrl+Alt+D for an endnote, Ctrl+Alt+M for a comment and Ctrl+Alt+L for a list-number field; **not verified on a machine here**). While this app runs, its own Ctrl+Alt+D (Review a draft) and Ctrl+Alt+L (My to-do list) would take those. Ask therefore starts as Ctrl+Alt+Shift+P (three modifiers). The earlier defaults were left unchanged; whether to move them is the owner's decision. Every shortcut can be rebound or, for Ask and the to-do list, removed in Settings. |
| Wrong-record display (identifier confusion) | A number labeled NDA, BLA, IND, DMF, MF or NDC is never treated as an ANDA, because those are also six digits and can coincide with a real ANDA number. Ambiguous labels decline and open the lookup box. |
| Diagnostic mode (`--selftest`) | Hermetic: its own data folder, no network calls, restores the user's clipboard, writes only to the folder it is given. It injects keystrokes to test hotkeys, so it says so and asks the user to leave the keyboard alone. CI uploads only its fictional-data output. |
| Crash log | A crash writes the exception text to `crash.log` in the app's data folder and shows its path. The app never logs record content, selections, prompts or keys; exception text is framework text. |
| Unsigned executable | The demo build is not code-signed, so SmartScreen warns. The release publishes a SHA-256 of the executable and of the zip. v1 requires signing and managed deployment; an organization's allow-listing may rightly block the prototype. |
| Compact boxes and focus | A compact box is shown without being activated: it cannot receive the keystrokes of someone typing in another window, and a stray Enter, Space or E cannot expand it. Expansion needs a click or a deliberate second hotkey press. Compact boxes make no AI call, so they send nothing anywhere. Auto-hide only ever closes windows; it reads no content and sends nothing. |
| Over-collection / telemetry | None. The extension writes only to its own browser storage. The app writes local files in `%AppData%\AndaCompanion`: `settings.json`, `prompts.json` and `todo.json` (and, once the round 18 design is ported, the recent and kept ANDA numbers inside `settings.json`) (user-readable JSON; `settings.json` stores the paths and column choices you set, never file contents), `usage.csv` only if you turn the usage log on, and `crash.log` only if it crashes. It reads `closures.txt` if you create it. It makes no network calls except the optional Anthropic endpoint, the optional Elsa endpoint, and, only when the person chooses them, My API and the one address behind Update now (all above), and requires no admin rights. **Phase 1 added no outbound host**: the holiday calendar is computed in the app, the draft check is deterministic, and the reference file is read from disk. Round 10 adds the two optional, person-started ones above, both unused until configured. `ANDA_COMPANION_HOME` relocates those files (the demo launcher uses it so nothing lands in the user profile). |
| Supply chain | Dependencies pinned by exact version (Avalonia 11.3.18, official Anthropic SDK 12.35.1); no post-install scripts; single-file publish. The CI workflow pins every third-party action to a commit SHA and uses the Windows runner's preinstalled .NET SDK rather than an extra setup action. v1: signed builds + SBOM in CI, IT-managed deployment (MSIX/Intune). |
| Model output as a decision | Every generated brief is labeled "generated — verify before acting," claims carry source refs, and the deterministic facts stand apart from AI text by design. The app is **read-only**: it can display, never modify, agency records. |
| Availability / fail-open behavior | Any AI-path failure (missing key, network, rate limit, refusal) silently degrades to the deterministic offline brief — the tool never blocks the user's work and never retries aggressively. |

## Rules of the road (enforced by code review on this repo)

1. No secret ever appears in settings, logs, source, or commit history.
2. No new outbound endpoint without updating this document.
3. Anything the model wrote is visually labeled as generated, wherever it is shown.
4. The app remains read-only against systems of record until a formal review says otherwise.
